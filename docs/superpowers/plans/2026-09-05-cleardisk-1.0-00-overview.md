# ClearDisk 1.0 — Plan Overview

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship ClearDisk 1.0 for direct download: free scanning, $10 one-time license bought on cleardisk.app, dark mode, one safe removal flow, hero-first scan, and the website.

**Architecture:** A native SwiftUI app (SPM package, `Core` engine + `ClearDiskApp` UI) talks once to a Cloudflare Worker for license activation and otherwise works offline. The Worker also serves the static website and handles Stripe. Five plans, one per milestone, executed in order; each leaves a shippable app.

**Tech Stack:** Swift 6 / SwiftUI / CryptoKit / IOKit (macOS 15+), XCTest; TypeScript Cloudflare Worker with KV, Email Sending binding, Stripe SDK, vitest + `@cloudflare/vitest-pool-workers`; plain HTML/CSS site.

## Global Constraints (apply to every task in every plan)

- Platform floor: macOS 15 (`Package.swift` `platforms: [.macOS(.v15)]`), Swift tools 6.0, strict concurrency. Existing code uses `@Observable` and `@MainActor`; keep to that.
- Bundle id `app.cleardisk.ClearDisk`; product name "ClearDisk" everywhere; URL scheme `cleardisk`.
- Price is displayed as **"$10"** everywhere (site and app); the app reads it from `Pricing.display`. Never write "$9.99".
- License key canonical form: `CLDK-` + 16 Crockford base32 characters in four dash-separated groups; alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ`. Derived as `HMAC-SHA256(KEY_SECRET, "cleardisk:v1:" + session.id)`, first 10 bytes.
- Receipt message: `"cleardisk:v1:" + key + ":" + machineId`, signed with Ed25519; app verifies offline with the embedded public key.
- Activation limit: 3 machines per key (`MAX_ACTIVATIONS` var).
- Email from `hello@cleardisk.app` through the Cloudflare `send_email` binding named `EMAIL`.
- Safety rule (enforced by `Scripts/make-app.sh`): `FileManager.removeItem` may appear only in `Sources/Core/TrashService.swift`. Never add another call site.
- Palette rule (enforced from plan 03 on): `Color(hex:` and `background(.white` may appear only in `Sources/ClearDiskApp/UI.swift`.
- Tests: `swift test` from the repo root must stay green (17 tests at start). Worker tests: `cd web && npm test`.
- Commit after every task with a short imperative message. Do not commit `dist/`, `.build/`, `web/node_modules/`.
- Build the bundle with `./Scripts/make-app.sh` (needs a signing identity; ad-hoc fallback works). Run in dev with `swift run -c release ClearDiskApp`.

## How the plans depend on each other

- 02 depends on 01 only at runtime (the app calls the deployed Worker). For local testing run `cd web && npx wrangler dev` and launch the app with `CLEARDISK_API=http://localhost:8787`.
- 02 moves `DestructiveButtonStyle` into `UI.swift` and deletes `DeleteForever.swift`; 03 restyles it. Do 02 before 03.
- 03's build guard forbids `Color(hex:` in view files; anything 02 adds must use `UI` tokens or existing `Color(hex:)` calls that 03 then replaces (03 lists them).
- 04 changes the `ParallelScan.scan` progress signature; `scan-cli` is updated in the same task.
- 05 needs the finished app for screenshots and the DMG from `Scripts/release-direct.sh`.
